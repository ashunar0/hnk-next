## 1. 検索とページネーション

invoices の一覧に、状態（draft / sent / paid）での絞り込みと、カーソルでのページ送りを足した。

### 予想

新しいファイルは要らない。既存の 4 ファイルの中で収まる（育ち方のどの動きにも当たらない）。

### 結果

予想どおり、ファイルは増えなかった。それぞれの置き場所はこうなった。

| もの                                                                               | 置き場所                   | 理由                                           |
| ---------------------------------------------------------------------------------- | -------------------------- | ---------------------------------------------- |
| 状態の種類（`invoiceStatuses`）                                                    | domain                     | モノの性質                                     |
| 新規作成は下書き                                                                   | service                    | 手順のルール                                   |
| 一覧の条件・ページ・位置の型（`InvoiceListQuery`、`InvoicePage`、`InvoiceCursor`） | service                    | 手順が保存に求める形。保存の形の宣言と並ぶ     |
| 1 件多く読んで続きを知る、キーセットの WHERE                                       | repo                       | 保存の技法                                     |
| カーソルを外から読めない文字列にする（base64）                                     | routes                     | HTTP での見せ方。Date を数値にするのと同じ種類 |
| 壊れたカーソルを 400 にする                                                        | routes（zod の transform） | 検査の失敗として自動で 400 になる              |
| limit の既定値と上限                                                               | routes                     | HTTP の入口でシステムを守る値                  |

### 引っかかったこと

1. **repo が domain の値を使いたくなった。** テーブルの `status` 列の取りうる値を `invoiceStatuses` から借りるため。
   DB の制約が domain のルールを写すのは自然なので、許可表を「repo → domain は値も可」に緩めた
2. **routes が service の型に名前で触れない。** ページの変換関数の引数に `InvoicePage` を使いたかったが、
   routes → service は禁止なので、`{ items: Invoice[]; next: Pick<Invoice, "updatedAt" | "id"> | null }` と構造で書いた。
   二重に書いている。routes → service を「型だけ可」にするかは未決
3. **query を宣言すると、hc で呼ぶときに引数が必須になる。** 項目が全部省略可能でも `$get({ query: {} })` と書く必要がある。形の問題ではなく使い勝手の話

### 確かめていないこと

- zod の transform を含む query で、`/openapi.json` の生成が通るか（実行時の話なので未確認）
- キーセットの WHERE が D1 で意図どおりに動くか
