# 06 を受けて: 組織と、他の module に見せる読み

作成日: 2026-10-10

06 のレビューで出た「組織・共有」のうち、組織と、reports が他の module の表を読む問題を直した。共有は次のステップ。

## 組織（98334c9）

- User が `orgId` を持つ。Reach に `{ kind: "org" }` を足し、`own` にも `orgId` を持たせた
- admin の範囲は、全員から「自分の組織の全員分」に（あさひ決定）。全組織を見られるのはシステムだけ
- reports は範囲の条件が無く、admin を組織内に絞ると他の組織を集計する状態だったので、同時に直した
- 本番データが無いので、migration は作り直した（`0000_init.sql` を消して再生成）

## 読みの入口（a3bbd3f）

迷いどころ: reports が invoices と payments の表を直接読んでいる。どうするか。

- Go に決まった答えは無い（sqlc で 1 か所に集める／使う側が interface／CQRS の読み側）。外部の意見も 2 つ聞いた
- 判断の軸: **「無いと書けてしまう間違い」は何か**。他の表への書き込みは、`scopeTo` ですでに書けない。残るのは **範囲の付け忘れ**
- 結論: 読む道を 1 本にする。持ち主が `〜Within(db, reach)` を出し、範囲は必須引数。生の表は外部キーの `references()` の中だけ。
  契約テストは登録なしで、export の `〜Within` を全部回す
- 見送り: 全 module の読みを 1 つの `readScope` にまとめるハブ（読み手が reports だけの間は要らない。2 つ目が現れたら）。
  読みの部品を別ファイルに切り出す案（lint を AST で書けたので、ファイルは増やさずに済んだ）
- 確かめたこと: 範囲の条件を壊すと、契約テストが invoices と payments の両方で落ちる。表を from に書くと lint が 1 件止める

## 共有（同じ組織の中、閲覧と編集の 2 段階、共有できるのは所有者と組織の admin）

- Reach の `own` を `member` に改名（自分のもの＋共有されたもの）。`invoice_shares` 表を invoices の repo に持たせた（新しい module は作らない）
- `findWithin` が行と一緒に access を返す。書き換えは edit 以上、消す・共有するのは manage だけ。判定は domain の純関数 1 か所
- 型テスト（`rpc.typetest.ts`）が「update に 403 は出ない」の変化を検知した。意図した変更なので期待を書き換えた
- 残したこと: 取り消しと書き込みの競合、相手の組織の確認、閲覧だけの人の支払い（README の未決）
