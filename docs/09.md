# AI に新しい module を書かせた実験（comments）

作成日: 2026-10-10

「invoices と同じ形で」と頼んだだけで、規約が漏れなく伝わるかを見た実験。漏れた所を、ルールの穴として拾う。

## 条件

- 書かせた相手: Sonnet のエージェント 1 回（worktree で隔離、約 3 分、約 10 万トークン）
- 渡したもの: 依頼文だけ。仕様は「請求書へのコメント」（本文 1〜1000 文字、請求書を見られる人が読み書き、消せるのは本人か組織の admin、請求書が消えたら一緒に消える、他の組織のものは見えない、一覧は古い順、HTTP は 3 本）
- 守らせたこと: `packages/hnk/` と `.oxlintrc.json` は変えない。通らなければ緩めずに報告する。commit しない
- 注意: README を読むなとは言わなかったので、エージェントは自分で読んでいた。「文書あり」と「なし」の比較はまだ。1 回だけなので傾向とは言えない
- 結果の作業ツリーは、ブランチ `worktree-agent-acde47be32b8cea75`（worktree `.claude/worktrees/agent-acde47be32b8cea75`）に残してある。main には取り込んでいない

## 結果

typecheck・lint・テスト 49 本が通った（こちらで再実行して確認）。変えた既存ファイルは `deps.ts`・`index.ts`・`deps.test.ts`・migration だけ。

揃っていた所:

- `domain / service / routes / repo.d1` の 4 ファイル、brand 付きの入力、`Comment` への詰め替え
- 他 module（invoices）を使うとき、comments が必要な形（`CommentableInvoices`）を宣言し、deps.ts で invoices の service とつなぐ。invoices を import しない
- 外部キーでだけ他 module の表を使う（`references()`）。`no-foreign-table-reads` に合う
- 失敗は NOT_FOUND / FORBIDDEN の Result、route は `reply`、200 と `{ ok: true }` は invoices に揃えた

## 規約の漏れの候補

| 候補                                     | 何が起きたか                                                                                                                                                          | 重さ |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| 一覧に上限が無い                         | invoices はカーソル式のページング。comments は件数無制限（仕様に書かなかったが、AI は忘れうる）。共通部品（ページング）の置き場が無いことと同じ根                     | 高   |
| HTTP の正常系を試せない                  | `withViewer` が常に null なので、route 層は 401 と OpenAPI の確認だけ。未決の「テストからログイン状態を作れない」                                                     | 高   |
| ID が string 同士                        | `find(invoiceId, id)` などは、引数の順を間違えても型で止まらない。未決の ID ブランド型の裏付け                                                                        | 中   |
| 子が親の見え方を引き継ぐ流儀が割れている | payments は join、`invoice_shares` は列なし、comments は親に問い合わせ。comments の選び方だと、他の module が comments を範囲付きで読むとき、組織の線を引く場所が無い | 中   |
| domain の暗黙の前提                      | `canDelete` は `role === "admin"` だけを見る。「同じ組織」は `invoices.get` が見えるかどうかに暗黙で頼っている                                                        | 中   |
| 文字列の trim の方針                     | invoices の title は trim、comments の body は trim しない（空白だけが通る）                                                                                          | 低   |
| 子 module の route の置き方              | `/invoices` に 2 つの router を mount した。動くが、親の下に置く決まりが無い                                                                                          | 低   |

迷わず揃えられた所（規約が効いた例）: 依存の向き、他 module との繋ぎ方、200 か 201 か（invoices に揃える）。
